## 🎯 一句话概括

EgoX 把「人、真机、仿真体」当成平等的三种形态，用一套**按解剖/功能对齐的模态词表**（ego 图像、躯干位姿、左右腕位姿、末端关键点）统一起异构示教，让每种形态只保留自己的 tokenizer 与 action expert、共享一个 Transformer 主干；再加一个**只在训练时存在的 embodiment dreaming**（预测未来视觉/本体潜变量）逼主干学各形态的动力学——13 个任务-形态组合上把平均归一化任务进度从 0.63 提到 0.80，OOD 从 0.53 提到 0.77。

## 💬 讨论与备注

- **它解决的是「异构数据怎么拼」而不是「怎么把模型做大」。** 主干加各形态模块只有 120M–185M 参数、图像骨干是 ResNet-18，收益全部来自表示与训练目标的设计。这在动辄数十亿参数的具身基础模型里是个反例，值得留意。
- **关键让步：不要求跨形态任务一致。** 数据集不是「同一套任务在所有形态上重跑」，而是各形态按自身能力贡献不同任务子集；跨形态重叠发生在**模态语义**层面，而非任务或关节空间层面。这是整篇论文成立的前提，也是最容易被误读的地方。
- **dreaming 是纯训练期开销。** 部署时丢掉 dreaming expert 与 EMA 教师，只保留学生 embodiment tokenizer，推理成本不变——这比「预测未来像素」一类的 world model 干净得多。
- **读数字时的提醒**：主指标是「归一化任务进度」而非成功率（成功率在附录 A.10）。进度分给中间阶段计分，所以 0.63→0.80 不完全等于「多做成了多少任务」；跨论文比较时不要与成功率混用。
- **作者自陈的硬伤**：数据全部由本团队自采（规模受限）；仿真只覆盖 1 个人形 + 2 个厨房任务；接入新形态仍需手工指定模态对应与坐标变换；每个形态等量采样，小数据集（LocoMan-Dex2 仅 37 条）被反复复用，有过拟合风险。
